The project is a useful local decision workspace with a credible evidence foundation, not yet a complete selling operations app. Canonical SQL owns758 lots/853 available copies; live status confirms559,072 eligible observations. Current code includes exact-product hydration, separate USD histories, sale samples, modeled proceeds, individualized dated AI reviews, broad buylist screening, continuous scrolling and card imagery. Standard self-sale preference is Mana Pool, per owner confirmation; alternatives matter only when worthwhile net evidence justifies them.

Public daily refresh is implemented; the maintained guide records an8AM Pacific Codex heartbeat. Latest retained successful report isOctober5,9:25AM PDT; individual source checks occurred about9:21AM. This assessment inspected the report, not a new full refresh or a witnessed scheduled run. The computer must be awake/Codex running. Current dealer quotes depend on authenticated TCGSentry export; public feeds do not establish fresh CK capacity. A scheduling declaration is not proof of unattended success across multiple days.

All758 lots have saved individual reviews, but the latest written review checkpoint precedes newer pricing and model-version changes. Live money and detectors recalculate; narrative interpretation does not automatically refresh. The app correctly labels earlier checkpoints, but this remains a substantive product gap for an AI-first experience.

## Findings requiring attention

1. Owner directions and notes remain browser drafts despite existing SQL owner-choice tables. No end-to-end accepted-quote, reservation, shipment or finalized-sale workflow exists. Browser drafts must be imported with explicit lot identity, preserving existing choices; this is the highest-value next implementation.
2. Historical median comparison is useful but can lag a new regime. Recompute supported recent-price scenarios and explicitly invalidate/review changed narratives. Prioritize meaningful dollar changes and contradictions; don't regenerate boilerplate for every unchanged card daily.
3. TCG dollar bases are not interchangeable. Documented seller-tool Last Sold Listing includes shipping, while the public graph's shipping basis remains unverified. Mana Pool merchandise price, shipping receipt and net are separate. Keep unknown-basis reference gaps from becoming claimed achievable premiums.
4. Weekly Mana Pool bars show deduplicated observed copies, not complete volume. With at most20 records/capture, missed sales cannot be recovered by counting dots or treating empty bars as zero market sales. Retained exact-grade supply trends and quote/capacity changes can corroborate activity. TCG UI volume is useful targeted evidence, not an established bulk collector.
5. Loader is functional but slow: recent measured full input load8–15seconds; activity query675ms. All historical points for758 lots are delivered upfront. Load list summaries first and fetch detailed histories on opening a card; index/query improvements and cache invalidation should follow actual measurements.
6. Daily collectors retain repeated full rolling history captures. Replay is safe, but long-term storage/query growth needs incremental observation storage without losing provenance. Implement before many months of daily accumulation.
7. MagicCon has researched methodology and an18-lot pilot, not a qualified Atlanta buyer roster or negotiated package. Require advance cash prices and written terms, price validity, quantity, grade deductions and quick verification handoff. Compare core-only versus core-plus-add-ons incremental payment. Protect easy CK alternatives.
8. Documentation accumulated conflicting historical counts/status claims. CURRENT_STATE is now concise; older checkpoints are archived and remain dated evidence. README and readiness metadata should identify historic scope rather than implying all captures are current.

## Recommended order

**Next: make choices durable and execution reviewable.** Persist owner plans/notes in canonical SQL; preserve and migrate browser drafts. Add a CK batch workspace with exact export identities, current bid/capacity, shared shipping, selected totals, accepted quote and status tracking. Record sold quantities through stock events only after owner execution. No automatic selling.

**Then: freshness-aware AI and faster exploration.** Serve compact collection summaries; load card histories on demand. Add a change queue for improved/worsened CK exits, repeated rising realized sales, changing supply and material quote conflicts. Save revised AI interpretations with pinned evidence and costs. Distinguish channel preference from sell-now timing.

**Then: build the MagicCon package.** Turn pilot into buyer-specific core/specialist/add-on modules with outside-alternative totals and paired quote comparisons. Qualify vendor attendance and price-first process a few weeks before the event; prepare packets for owner review before outreach.

**Selective enrichment after that.** Target eBay/TCG completed-sale and volume research at high-value cards or genuine conflicts. Add corroborated demand/reprint context where it can change a decision. More price columns across every card is lower value than dependable execution and fresh analysis.

## Completion standard

A card's next move should be visible in seconds, with dollars and a concise reason. The owner can select a batch, obtain an exact quote, record completion and retain an auditable history across browsers/devices. Valid scheduled updates apply automatically; failures retain last-good data and notify only when material. Unknown data never becomes zero or invented certainty. Desktop-first, mobile-capable, local SQL remains appropriate; no cloud migration needed yet.
